# Angel Tears

Sistema web para un pequeño negocio de accesorios: presencia pública con catálogo y administración interna de productos, inventario, proveedores, compras, ventas y egresos.

## Estado actual

**Planificación y arquitectura. La implementación todavía no comenzó.** Este repositorio establece una base documental común para el equipo, Codex, Claude Code y la revisión humana. No contiene aplicación ni dependencias.

El MVP público incluye información del negocio, catálogo, contacto y SEO/indexabilidad, desde celular y computadora. El administrativo permite registrar operaciones y consultar un resultado económico aproximado. Carrito, pagos online y pedidos web quedan fuera del MVP.

## Cómo empezar

1. Leer [producto](docs/PRODUCTO.md), [alcance](docs/ALCANCE.md) y [reglas del dominio](docs/REGLAS_DOMINIO.md).
2. Revisar [arquitectura](docs/ARQUITECTURA.md), [ADR](docs/adr/README.md) y [decisiones pendientes](docs/DECISIONES_PENDIENTES.md).
3. Seguir [desarrollo](docs/DESARROLLO.md), [flujo Git](docs/GIT_WORKFLOW.md) y [definición de terminado](docs/DEFINICION_TERMINADO.md).
4. Consultar [plan de implementación](docs/PLAN_IMPLEMENTACION.md), [UX/UI](docs/UX_UI.md), [calidad](docs/CALIDAD.md), [seguridad](docs/SEGURIDAD.md) y [testing](docs/TESTING.md).

Los agentes deben leer [AGENTS.md](AGENTS.md). Las tareas futuras se preparan con la [plantilla de feature](docs/features/TEMPLATE.md).

La IA no es la fuente de verdad. La SRS validada y los artefactos RUP corregidos tienen prioridad; aún no fueron incorporados. La trazabilidad RF/CU queda pendiente de esas fuentes. Next.js, TypeScript y PostgreSQL son una propuesta pendiente de validación grupal.
